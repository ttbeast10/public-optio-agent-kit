# Changelog

## 0.4.0 — 2026-11-03

- New `deploy/` starter: run Optio from the released Helm chart and images only, with no source code and
  no source changes, and its work as configuration as code. `deploy/init.sh` copies it into a deploy
  repo (kit-owned files updated, `values/`, `config/`, `site/site-facts.md` never overwritten).
- `deploy/README.md`: the plan in phases 0–7, and each chart / image gap at `d72f1cd1` with the
  configuration that covers it — hardcoded `busybox` (node registry rewrite), no pull secret on agent
  pods (own ServiceAccount), no free-form env or CA value (`existingSecrets`, `api.extraVolumes`), agent
  images without the site CA (`agent-ca.Dockerfile`), private egress (`networkPolicy.extraEgress`), the
  Ingress `server-snippet`, the LLM gateway (`ANTHROPIC_BASE_URL` pod secret), Jira Data Center (HTTP
  connection through the REST bridge; event trigger after a test), Helm `lookup` under Argo CD.
- Scripts: `bundle/fetch.sh` (outside) / `load.sh`, `images/build-agent-ca.sh`,
  `scripts/make-k8s-objects.sh`, `deploy.sh`, `apply-config.sh`, `bootstrap-db.sh`, `verify.sh`,
  `check-values.sh`.
- `CLAUDE.md` and skills `optio-deploy`, `optio-config-as-code` for the agent running the deploy repo.
- Tests: deploy scripts' syntax, values keys known to the chart, flat config with every `*File` present,
  `init.sh` idempotent and keeping team files.

## 0.3.0 — 2026-11-03

- `helm/VALUES-MAP.md`, generated by the new `scripts/helm-value-map.sh` (bash + awk, no helm): every Helm
  value → template → env var → reading source files; env vars the API reads that the chart never sets
  (86 at `d72f1cd1`, incl. `GITLAB_HOSTS`, `GITLAB_OAUTH_BASE_URL`, `GITLAB_TOKEN`, `OPTIO_MAX_CONCURRENT`);
  `values.yaml` keys no template reads (`api.strategy.type`, `agent.image.pullPolicy`,
  `agent.envoyProxy.image.pullPolicy`). Follows `include` helpers, `with`/`range` scopes, `dig`, `index`,
  `$variables` and `if`-guarded constants.
- `install.sh` generates the map from the target checkout; `check-agent-guides.sh` fails while it is stale;
  `make-pr.sh` includes it in the upstream PR.
- `helm/AGENTS.md` rewritten: main ideas now cover data stores, scaling, exposure, egress, operations
  (metrics, OpenTelemetry, backups, quotas, config as code), features and sign-in, and secret persistence.
- Air-gap layer: `helm/CLAUDE.md`, routing table, `optio-refresh-guides` and `impact.sh` point at the map.

## 0.2.0 — 2026-11-02

- Split into two layers: `core` (generic, upstream-able) and `airgap` (our fork).
- Area guides are now `AGENTS.md` files with each area's **main ideas**, plus `CLAUDE.md` shims that import
  them; new guides for `apps/cli` and each package; `docs/agent-guides/README.md` explains Optio in one page.
- Air-gap layer: `docs/airgap/README.md` (what the fork is, how we work) and the team-owned
  `docs/airgap/worklog.md` (now, decisions, log) read at the start and end of every task.
- Everything works inside the air gap; the outside-Claude workflow is kept only as a future plan.
- New skill `optio-refresh-guides`; `optio-sync-upstream` rewritten for inside-only syncs.
- Tooling: `install.sh` (layers, dry run, prune, idempotent), `harvest.sh`, `make-pr.sh`, `tests/run-tests.sh`.
- `scripts/check-agent-guides.sh` replaces `verify-guides.sh` and also checks `@` imports.
