## docs(agents): add area guides with main ideas for coding agents

### Why

The root `AGENTS.md` is the single source of agent context: about 67 KB (~30k tokens), loaded whole into
every session through `CLAUDE.md`. Strong models cope; smaller and faster ones (and teams on token budgets)
spend their first turns reading broadly and still miss the right file. Claude Code's built-in Explore/Plan
subagents also start without `CLAUDE.md`, so wide searches run with no map at all.

### What

- `docs/agent-guides/README.md` — Optio's main ideas on one page (the work model and its five attributes,
  pod-per-repo and the run protocol, the life of a Repo Task, the control plane and reconciler,
  integrations, ownership) plus an index of the area guides.
- A short `AGENTS.md` in each main area — `apps/api`, `apps/api/src/services`, `apps/web`, `apps/cli`,
  `packages/shared`, `packages/ticket-providers`, `packages/agent-adapters`, `packages/container-runtime`,
  `packages/mcp-bridge`, `helm`, `images`, `scripts` — each with: what it is, main ideas, a file map, and
  how to change it safely. The services guide groups the ~240 flat service modules by domain.
- Next to each, a `CLAUDE.md` containing `@AGENTS.md`, mirroring the root convention: Claude Code loads it
  when it works in that folder; Codex/OpenCode read the `AGENTS.md` directly.
- A "Start here" section near the top of the root `AGENTS.md` pointing to the guides (between
  `agent-guides` markers). Nothing else in the root file changes.
- `helm/VALUES-MAP.md`, generated by `scripts/helm-value-map.sh`: every Helm value → the template that uses
  it → the env var it becomes → the source files that read that env var; the env vars the API reads that the
  chart never sets (only `existingSecrets` can set them today); and `values.yaml` keys no template reads
  (currently `api.strategy.type`, `agent.image.pullPolicy`, `agent.envoyProxy.image.pullPolicy`). Static
  reading of the templates: follows `include`, `with`/`range`, `dig`, `$variables`; no helm needed.
- `scripts/check-agent-guides.sh` — exits non-zero when a guide names a file that no longer exists, a
  `CLAUDE.md` import doesn't resolve, or `helm/VALUES-MAP.md` is out of date; lists service modules the
  services guide doesn't mention yet. Bash + git only; could join CI next to `check-migration-prefixes.sh`.

Docs only: no runtime code, images or chart changes.

### How it was checked

- `bash scripts/check-agent-guides.sh` → 0 missing on this branch; `bash scripts/helm-value-map.sh --check` passes.
- Value map rows were spot-checked against the templates (e.g. `agent.image.prefix` → `OPTIO_AGENT_IMAGE_PREFIX`
  → `repo-pool-service.ts`; `auth.oidc.*` → `OIDC_*` → `sign-in-env.ts`).
- Every guide is Prettier-formatted (`pnpm format:check`).
- Facts were taken from the code and the existing docs (`docs/tasks.md`, `docs/reconciliation.md`,
  `docs/connections.md`, …); each guide links its long-form doc instead of repeating it.

### Keeping them true

The guides are short on purpose; the check script catches moved files. A guide that drifts in substance is
fixed like any doc.
